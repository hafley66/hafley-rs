# Rollback networking

Scope: engine-independent candidates only. Discovery stopped at 8 external retrieval calls. `D` = official documentation, `S` = official source tree, `M` = manifest, `T` = official test/support path, `R` = release metadata, `I` = inference from those records.

## Qualified candidates

### GGRS

**Version/source.** Current `main`; release metadata lists `v0.13.0` ([release page](https://github.com/gschup/ggrs/releases), tag commit `[UK]`). The page exposes `v0.12.0` at `21e7e5a`. Sources: [`docs/requests-and-events.md`](https://github.com/gschup/ggrs/blob/main/docs/requests-and-events.md), [`docs/main-loop.md`](https://github.com/gschup/ggrs/blob/main/docs/main-loop.md), [`docs/sparse-saving.md`](https://github.com/gschup/ggrs/blob/main/docs/sparse-saving.md), [`src/sessions/p2p_session.rs`](https://github.com/gschup/ggrs/blob/main/src/sessions/p2p_session.rs), [`src/sessions/sync_test_session.rs`](https://github.com/gschup/ggrs/blob/main/src/sessions/sync_test_session.rs), [`Cargo.toml`](https://github.com/gschup/ggrs/blob/main/Cargo.toml). Evidence: D/S/M/R.

**Contract claim.** `P2PSession::advance_frame(&mut self) -> Result<Vec<GgrsRequest<T>>, GgrsError>` returns ordered requests. The application handles every request in order: `SaveGameState { cell, frame }`, `LoadGameState { cell, frame }`, and `AdvanceFrame { inputs }`. Save calls `cell.save(frame, Some(state), Some(checksum))`; load calls `cell.load()` and restores the state; advance performs one deterministic simulation step from the supplied input set. `poll_remote_clients()` is called every loop, and local input is added before advancing. Evidence: D/S, symbols above. Engine coupling: none in the core; examples and wrappers are separate. Application-owned state: complete simulation state, serializer/restorer, checksum, frame timing, side-effect gating, and input mapping. Constraints: save state must correspond to the request frame; `cell.load()` clones stored state and needs `T::State: Clone`; `cell.data()` provides read-only access without that load clone. Default saving is every frame, with up to `max_prediction_window + 1` save slots; sparse saving reduces save requests and can lengthen re-simulation. Unknowns: exact current `Config` bounds, allocator behavior inside request/history paths, and `v0.13.0` tag commit are `[UK]`.

**Transport/desync/replay claim.** P2P sessions use a nonblocking socket abstraction and the documented loop exchanges UDP packets; Matchbox supplies a WebRTC socket adapter. `GgrsEvent::DesyncDetected { frame, local_checksum, remote_checksum, addr }` reports divergent checksums when save callbacks supply them. `SyncTestSession` is local-only, re-runs a configured recent distance every frame, and compares checksums. Evidence: D/S/T, [`docs/main-loop.md`](https://github.com/gschup/ggrs/blob/main/docs/main-loop.md), [`docs/sessions.md`](https://github.com/gschup/ggrs/blob/main/docs/sessions.md). Engine coupling: transport adapter only. State: application checksum defines the compared state. Constraints: deterministic simulation must include every outcome-affecting value, including time/RNG/order; rendering and audio can remain outside state if they do not affect outcomes. Unknowns: exact socket feature matrix and allocation counts are `[UK]`.

### Backroll-rs

**Version/source.** Repository `main`, version and commit `[UK]`; its workspace manifest lists `backroll`, `backroll_transport`, `backroll_transport_udp`, and `backroll_transport_steam` ([`Cargo.toml`](https://github.com/HouraiTeahouse/backroll-rs/blob/main/Cargo.toml)). Official README: [`README.md`](https://github.com/HouraiTeahouse/backroll-rs/blob/main/README.md). Evidence: M/D.

**Claim record.** Backroll describes itself as pure Rust GGPO-style rollback. Its README states generic/associated-type state handling intended to avoid serialization overhead, abstract transports, runtime configuration, raw UDP, Steam networking, and async-task-pool I/O. Engine coupling: core crates are engine-independent; `bevy_backroll` is a separate integration and is excluded. Application-owned state: `[UK]`; exact save/load/advance symbols, callback/request ordering, checksum/desync API, replay or sync-test API, and state lifetime are `[UK]`. Constraints: README labels the project early beta with limited testing and possible undiscovered bugs; exact current crate versions, MSRV, allocation guarantees, and platform matrix are `[UK]`. Evidence category: D, with source paths visible in the repository tree. This candidate remains qualified for transport and architecture comparison, with the rollback contract requiring direct source verification in the proposed experiment.

### GGPO

**Version/source.** Official `master`; GitHub reports no packaged releases, so version and current commit are `[UK]`. Sources: [`README.md`](https://github.com/pond3r/ggpo/blob/master/README.md), [`doc/DeveloperGuide.md`](https://github.com/pond3r/ggpo/blob/master/doc/DeveloperGuide.md), [`src/include/ggponet.h`](https://github.com/pond3r/ggpo/blob/master/src/include/ggponet.h), [`src/lib/ggpo/sync.cpp`](https://github.com/pond3r/ggpo/blob/master/src/lib/ggpo/sync.cpp). Evidence: D/S/R.

**Contract claim.** `GGPOSessionCallbacks` requires `begin_game`, `advance_frame`, `load_game_state`, `save_game_state`, `free_buffer`, and `on_event`. The guide gives `ggpo_save_game_state_callback(unsigned char **buffer, int *len, int *checksum, int frame)` and `ggpo_load_game_state_callback(unsigned char *buffer, int len)`. Save allocates a restorable buffer and returns its length/checksum; load restores it; GGPO calls `free_buffer` when the buffer is no longer needed; `advance_frame` executes one simulation frame. Evidence: D, symbols above. Engine coupling: none in the SDK; Vector War is a sample. Application-owned state: all outcome-affecting game state, buffer allocation/freeing, deterministic frame advance, and input interpretation. Constraints: guide requires a fully deterministic simulation, fully encapsulated serializable state, and single-frame save/load/execute without rendering. The README currently documents Windows-only building. Unknowns: exact `advance_frame` signature, checksum comparison/event details, buffer retention limits, and current cross-platform status are `[UK]`.

**Transport/replay claim.** `ggponet_start_session` accepts a local port and peer address/port; the SDK is P2P and exchanges inputs rather than full state. The official docs describe a Sync Test backend using the same sync object to verify save/step determinism. Evidence: D/T. Engine coupling: socket/session API only. State: application callback buffer. Constraints: callback allocations must remain valid until `free_buffer`; fixed-size reusable buffers require an application allocator and a verified lifetime policy. Unknowns: current test commands and desync event symbol are `[UK]`.

## Brief exclusions

Bevy-specific rollback integrations are excluded by the queue. Matchbox and similar networking packages are transport/matchmaking components, not complete save/load/advance rollback runtimes. No additional candidate was promoted after the retrieval bound.

## Proposed runnable experiment

Headless, deterministic harness using GGRS `SyncTestSession`, then the same state adapter against two P2P sessions. Use 60 FPS, 600 frames, prediction window 8, fixed-point positions/velocities, seed `0x5eed`, and two players. Inputs: player 0 holds left on frames where `frame % 120 < 30` and presses jump when `frame % 47 == 0`; player 1 holds right where `frame % 90 < 20` and presses attack when `frame % 53 == 0`. Deliver remote inputs with a 3-frame delay, delay frames 117 and 318 by 6 frames, and deliver them out of order once.

Assertions: every save/load frame matches its request frame; replay from each saved frame reproduces the baseline checksum; both peers end with the same checksum; no `DesyncDetected` occurs for the unmodified state; flipping one serialized byte at frame 400 produces a sync-test mismatch or desync event. Measurements: state bytes, save/load/advance allocations, save count, rollback count and maximum depth, serialized bytes, packets, and p50/p99 simulation time. Run status: **not run**, per instruction. No visible experiment or MP4 is expected.
