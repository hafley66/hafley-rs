## Verbatim research

### TL;DR
- A real cluster of open-source tools now builds cross-file code graphs from per-file tree-sitter parses with heuristic call resolution (same-file preference, unique-name-in-corpus, import clause, module path, spelled receiver type), stores them as SQLite or JSONL, and serves them to LLM agents over MCP; the strongest engineered examples for Rust and TypeScript are sdsrss/code-graph-mcp, bartolli/codanna, nodedb-lab/code2graph, brandyn-s/code-graph, and GlitterKill/sdl-mcp.
- Almost none publish edge-level precision/recall of the heuristic resolver against a SCIP or compiler oracle; the tools that even have the plumbing to do it (brandyn-s/code-graph's SCIP tier, code2graph's SCIP-aligned two-tier resolver, and the rag-rat oracle subsystem behind the Chris S Medium bytecode-oracle study) either keep the numbers in unfetchable docs or report them only as qualitative "grep < tree-sitter < SCIP" findings.
- Refactoring on top of a compilerless graph is rare: codelens-engine (Rust, with move_symbol and rename), GitNexus (TypeScript rename), and non-graph AST editors (Harn, plumb, revise-mcp, semantic-edit-mcp) do move/rename, but move-file-with-import-rewrite for both Rust and TypeScript without a language server is essentially unsolved in this corpus.

### Key Findings
- The dominant architecture is a two-pass pipeline: pass 1 is a per-file tree-sitter extraction of symbols, calls, imports/exports, receivers, and references; pass 2 is a batch cross-file "resolve" that binds call sites to definitions by heuristic. This is documented explicitly in sdsrss/code-graph-mcp, DeusData/codebase-memory-mcp (arXiv:2603.27277), GlitterKill/sdl-mcp, and nodedb-lab/code2graph.
- The best-engineered heuristics are converging on fail-closed receiver resolution. sdsrss/code-graph-mcp binds `obj.method()` only when exactly one same-language method carries that name and drops it when ambiguous; bartolli/codanna makes method calls on receivers whose type is neither inferred nor indexed fail closed instead of resolving by insertion order. Both treat unresolved-but-honest as better than fanned-out-and-wrong.
- Confidence and provenance columns are now standard. code2graph tags every edge with Confidence (NameOnly / Scoped / Exact) and Provenance; brandyn-s/code-graph attaches resolution_source, confidence_tier, confidence_band, and numeric_confidence to every edge; sdl-mcp attaches a 0.0 to 1.0 confidence, a resolver ID, and a provenance trace; the codegraph/graphify family tags edges EXTRACTED / INFERRED / AMBIGUOUS.
- The "slow lane" that cross-checks heuristics against SCIP exists in three places: brandyn-s/code-graph (opt-in SCIP tier for Go/TypeScript), code2graph (SCIP-aligned SymbolId, oracle eval against rust-analyzer scip and scip-typescript), and the rag-rat oracle subsystem (rag_rat_oracle crate; consumes rust-analyzer scip and scip-typescript, writes edge_oracle rows and precision/recall metrics; MCP tool compare_graph_to_scip).
- Published precision/recall against a true compiler oracle is scarce. The clearest public number is from the Chris S Medium study using a compiled-bytecode (javap) oracle over Hazelcast: SCIP recall is roughly 0.97 while the source-parse approaches (grep, tree-sitter) sit at roughly 0.3 to 0.5, and all three arms are similarly precise. The canonical academic baseline is PyCG (Python): per Salis et al. (arXiv:2103.00587, ICSE 2021), "PyCG achieves high rates of precision ~99.2%, and adequate recall ~69.9%."

### Per-tool mechanism notes

**sdsrss/code-graph-mcp (Rust, MIT, 75 stars, 13 forks, 1,278 commits).** Three-phase indexer with a BLAKE3 Merkle tree for incrementality; SQLite schema v10 with FTS5 and sqlite-vec. Resolution is name-based with same-file targets preferred over cross-file to cut false-positive edges. Known and documented resolution boundaries: a method reached through a module path (`Type::method()`) produces no edge, while a bare `Type::method()` and free functions through a path do resolve; a receiver call `obj.method()` binds only when exactly one same-language method carries that name and is dropped when the name is shared (verified by tests `receiver_call_resolves_unique_method` and `receiver_call_with_ambiguous_method_name_stays_unresolved`). Cross-file constant/type-position uses and callbacks are carried as a separate `references` relation, not as call edges. No move/rename. Benchmarks are tool-call-count reductions and a byte-ratio effectiveness test (0.04x on a fixture at v0.123.0), not precision/recall.

**DeusData/codebase-memory-mcp (C, MIT, ~43.2k stars, 3.5k forks).** The highest-starred tool in the space and the reference implementation for the arXiv:2603.27277 paper. Six-phase tree-sitter pipeline with a pthreads work-stealing pool writing to SQLite; XXH3 file hashing for incremental re-parse. The name-based cascade operates on string-level callee tokens; a "Hybrid LSP" / "LSP-Style Hybrid Type Resolution" pass adds in-process type inference for method receivers, pointer types, and similar constructs for about a dozen languages including Rust, TypeScript, Go, and Kotlin. Resolved calls carry a fully-qualified callee and bypass the string cascade. 14 to 15 typed MCP tools including a Cypher-like query_graph and trace_call_path. No move/rename. Notable forks: win4r/codebase-memory-mcp-pro (C), iflow-mcp/deusdata-codebase-memory-mcp (Go rewrite claim), xiaocongyu66/cbm-rs (Rust rewrite).

**brandyn-s/code-graph (Go, MIT, fork of codebase-memory-mcp).** Adds the exact "slow lane" the target shape describes: an optional compiler-index (SCIP) tier that upgrades heuristic tree-sitter edges to compiler-resolved edges per document for Go and TypeScript, plus a CODE_GRAPH_RESOLVER_TIER=lsp_local hybrid local-inference tier for Python and Rust (annotated parameters, pytest fixtures, and base-class method lookup become receiver types). Every edge carries an evidence contract (resolution_source such as lsp_direct, confidence_tier such as extracted, confidence_band, numeric_confidence, source_revision, index_generation). The index is bound to one checkout and fails closed with stale_source when the working tree drifts. A docs/measured-evidence.md is advertised as "precision/recall against oracles" but its per-language table is not retrievable from the public web; the only concrete number surfaced is a flask lsp_local delta in the CHANGELOG (unresolved call sites 1,810 to 1,674, CALLS edges 983 to 1,081, adversarial F1 0.588 to 0.585). No move/rename.

**nodedb-lab/code2graph (Rust library, Apache-2.0, v0.0.0-beta.17, 29 Jul 2026).** The cleanest expression of the tiered-resolver idea: a purpose-neutral extraction library (source to FileFacts to CodeGraph) with no storage, scoring, or embeddings. Two resolvers emit the same schema: SymbolTableResolver (recall-first, name matching, all 23 languages, NameOnly edges) and ScopeGraphResolver (lexical-scope + import + qualified-path resolution, Scoped/Exact edges, Rust/Python/TypeScript). Identity is SCIP-aligned (structural SymbolId with SCIP-renderable display). FfiBridgeResolver links Rust `#[no_mangle]` to C across a language boundary; IncrementalGraph re-resolves one file at a time. The design explicitly targets eval against SCIP oracles from rust-analyzer and scip-typescript, but no scorecard numbers appear on the repo README or docs.rs. No move/rename.

**bartolli/codanna (Rust, Apache-2.0).** tree-sitter parsing hits 91,318 symbols/sec on Rust and 75,047 on Python (per codanna project docs); Tantivy full-text plus HNSW semantic plus a memory-mapped symbol cache for sub-10ms lookups. Resolution hardening is the selling point: method calls on receivers whose type is neither inferred nor indexed fail closed instead of resolving by insertion order; call sites attribute to the enclosing same-name symbol so a test stub no longer absorbs the real function's callers; import-path matching respects segment boundaries (crate::widgets no longer matches crate::widget); tsconfig/JS-TS path-alias resolution. 16+ languages with Rust/TypeScript/Python/Go/PHP most complete. No move/rename tool. Star count not captured in this pass.

**abhigyanpatwari/GitNexus (TypeScript).** A zero-server engine: tree-sitter (native for CLI, WASM for browser) into LadybugDB, a KuzuDB-derived embedded columnar graph, stored in .gitnexus/. Every edge is structurally extracted from the AST with no LLM pass. Cross-language resolution refinements include carrying generic method type-parameters (a bounded T grounds to its bound, an implementor's concrete argument compares equal) and a hard interface-dispatch fan-out cap of 32. Optional per-function CFG/PDG for TS/JS. Ships a rename tool that combines graph and text search. License reported as PolyForm Noncommercial in project materials; not independently confirmed in this research pass.

**GlitterKill/sdl-mcp (TypeScript, npm v0.13.3).** "Symbol Delta Ledger": tree-sitter for repository structure with an extensible pass-2 resolver registry (one dedicated resolver per language) that traces imports, aliases, barrel re-exports, and tagged templates. Every resolved call edge carries a confidence score (0.0 to 1.0), a resolver ID, and a human-readable provenance trace. Provider-first indexing lets it ingest SCIP and LSP facts to add precise cross-references on covered files and fall back to the tree-sitter path elsewhere, matching the "optional slow lane" pattern. Has editing tools (file.write, symbol.edit, search.edit) with an overlay/staged-write model, but not a graph-driven move-file-with-import-rewrite.

**codelens-engine (Rust).** The one library in the set built around refactor safety: oxc-based JS/TS scope analysis, scope_analysis and type_hierarchy modules, and mutation primitives rename::apply_rename, move_symbol::MoveAction, and auto_import::add_import. Mutations must be routed through codelens-mcp's dispatch pipeline (role gates, audit, cache invalidation). This is the closest candidate to graph-backed move/rename without a language server, though its exact language coverage for import rewriting was not fully captured.

**crowl (Go, v0.1).** Confirmed to exist as a Go CLI (github.com/sonuverma1/crowl) using tree-sitter plus a go/types pass, but too early-stage to characterize resolution accuracy or output format.

### Adjacent tools worth knowing
- **cq27-dev/rag-rat** (Rust): the rag_rat_oracle crate consumes a pre-built SCIP index (rust-analyzer scip, scip-typescript) as a resolution oracle for its tree-sitter graph, writes edge_oracle rows, and emits precision/recall metrics; MCP tools compare_graph_to_scip and compare_graph_to_text. This is the productized "slow lane" and is the engine behind the Chris S bytecode-oracle study.
- **intuit/infigraph** (open source): tree-sitter for 62 languages plus SCIP auto-download (TypeScript, Python, Java, Go, Rust, C#, Ruby, Scala) with an lsp-to-scip bridge; import-aware cross-file resolution; full Cypher.
- **CodeGraphContext** and **lzehrung/codegraph**: tree-sitter with optional SCIP ingestion.
- **AST editors that do rename/move without a graph**: Harn's edit_rename_symbol (cross-file, tree-sitter, refuses on name collision; Rust, TS/TSX, JS/JSX, Python, Swift, Go), plumbkit/plumb move_symbol (LSP with tree-sitter fallback, same-directory only, explicitly refuses import-path-changing moves), davidfstr/revise-mcp (28 AST tools, 11 languages, rename-symbol and add-import), and semantic-edit-mcp (Rust, tree-sitter). molaco/rust-code-mcp does rename but is rust-analyzer-backed and therefore outside the compilerless scope.

### Papers
- **Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP** (Vogel, Meyer-Eschenbach, Kohler, Grünewald, Balzer), arXiv:2603.27277, 28 Mar 2026, CC BY 4.0. 66 languages, evaluated on 31 repositories: 83% answer quality vs 92% for a file-exploration agent, at 10x fewer tokens and 2.1x fewer tool calls; matches or beats the explorer on graph-native queries for 19 of 31 languages. Does not report edge-level precision/recall against a compiler oracle.
- **Repository Intelligence Graph: Deterministic Architectural Map for LLM Code Assistants** (Cherny-Shahar, Yehudai), arXiv:2601.10112, 16 Jan 2026. Deterministic build/test-artifact graph (components, aggregators, runners, tests, external packages) via the SPADE extractor (CMake File API + CTest), exposed as LLM-friendly JSON; evaluated with three commercial agents (Claude Code, Cursor, Codex) on eight repos. Build/test structure, not call-graph resolution.
- **RepoGraph** (Ouyang et al.), arXiv:2410.14684, ICLR 2025. Line-level nodes with definition/use edges, ego-subgraph retrieval as a plug-in; per the paper, "RepoGraph boosts the success rate of existing methods for both agent and procedural frameworks by achieving an average relative improvement of 32.8%" on SWE-bench.
- **CodexGraph** (Liu et al.), arXiv:2408.03910, NAACL 2025. Indexes a repository into a Neo4j graph queried by the agent via Cypher.
- **LocAgent: Graph-Guided LLM Agents for Code Localization** (ACL 2025 long). Parses codebases into directed heterogeneous graphs for multi-hop localization with unified retrieval tools.
- Others in the lineage: CGM/Code Graph Model (arXiv:2505.16901), GraphCoder (arXiv:2406.07003), LogicLens (arXiv:2601.10773), LARGER (arXiv:2605.16352), The Thousand-Graph Hypothesis (arXiv:2608.26602), GREPO (arXiv:2602.13921, GNN repo-level bug localization, tree-sitter + Jedi). The canonical Python call-graph accuracy baseline is **PyCG** (Salis et al., arXiv:2103.00587, ICSE 2021): "PyCG achieves high rates of precision ~99.2%, and adequate recall ~69.9%," running in about 0.38 seconds per 1k LoC. Its named follow-up, **JARVIS** (arXiv:2305.05949), reports being "at least 84% higher in precision, and at least 20% higher in recall" over PyCG.

### Blog posts
- **"Where a semantic code index finally beats grep: type-resolved reachability"** (Chris S, Medium, June 2026). The single most relevant data point: 12 type-reachability questions on Hazelcast (~2M LOC, pinned commit 7af6ddea), scored against an independent compiled-bytecode oracle built by running javap over 9,547 .class files. Result is a monotone grep < tree-sitter < SCIP: SCIP recall roughly 0.97 while grep and tree-sitter sit at roughly 0.3 to 0.5, all three arms similarly precise; SCIP wins the lexical controls too (about 0.975 vs grep's 0.482); on one hierarchy (DataSerializable) SCIP matched the oracle at precision 0.955, recall 0.986, F1 0.97; SCIP best-or-tied on 11 of 12 questions, grep on 0; grep-iterative averaged 102 passes per question (up to 481). This is the "bytecode-oracle" comparison and is powered by rag-rat. Full per-arm tables live in the article's images and the repo doc 2026-06-02-arenaA-graded-results.md.
- **"Grep vs. Graph: Two Ways an AI Can Read Your Code"** (Lince Mathew, Medium). Tests CodeGraph on seven real repos (VS Code, Django, Tokio, others): roughly half the tokens and well over half the tool calls versus grep-style search.
- **"Code Intelligence & Code-Graph Indexing for AI Agents"** (Anthony West). Survey of local indexers, SCIP, and the tree-sitter vs LSP/SCIP vs embedding trade-off; cites the Codebase-Memory 10x/2.1x figures.
- GitNexus write-ups: Termdock, Sidharth Satapathy, and MarkTechPost (all describe the AST-only, no-LLM edge extraction and LadybugDB storage).

### Excluded tools (mentioned briefly, per scope)
Sourcegraph SCIP indexers, GitHub stack-graphs (archived 9 Sept 2025), Joern, CodeQL, rust-analyzer, aider's repo-map, Cody, Continue, Cursor's index, Sweep, and tree-sitter-graph alone are all out of scope: they are either compiler/LSP-backed, archived, or a DSL rather than a resolving graph. Notably, at least two projects in this space explicitly abandoned stack-graphs after the September 2025 archival in favor of tree-sitter heuristics (documented in the sheeptechnologies/crader RFC 001 discussion).

### Recommendations
- If you want a batteries-included Rust+TypeScript graph today with the safest heuristics, start with **bartolli/codanna** (fail-closed receivers, tsconfig alias resolution, segment-boundary import matching) or **sdsrss/code-graph-mcp** (documented resolution boundaries, same-file preference, SQLite output). Both are MIT/Apache and production-shaped.
- If you specifically need the heuristic-then-SCIP "slow lane" with per-edge provenance, use **brandyn-s/code-graph** (SCIP tier for Go/TS, lsp_local for Python/Rust, evidence contract) or embed **nodedb-lab/code2graph** as a library and drive its ScopeGraphResolver, then reconcile against rust-analyzer scip and scip-typescript yourself. For a ready-made oracle harness, adopt **cq27-dev/rag-rat**'s compare_graph_to_scip.
- If you need JSONL rather than SQLite, note that none of the primary tools emit JSONL tables natively; code2graph's neutral FileFacts/CodeGraph are the easiest to serialize to JSONL, and codelens-engine emits daily-rotated JSONL for metrics (not for the graph itself). Budget engineering for a serializer.
- For move-file-with-import-rewrite or rename without a language server: **codelens-engine** (move_symbol + rename) is the only graph-backed Rust option, and **Harn**'s edit_rename_symbol is the cleanest cross-file rename for both Rust and TypeScript; combine one of these with a graph tool for reference discovery. Do not expect correct import-path rewriting on moves; plumb explicitly refuses it.
- Before trusting any heuristic graph in a token-sensitive or refactoring pipeline, run your own edge-level eval against a SCIP oracle (rust-analyzer scip for Rust, scip-typescript for TS). The Chris S study is the template: pin the commit and scope, use an oracle independent of all arms, and expect heuristic recall in the 0.3 to 0.5 range with high precision unless a SCIP tier is enabled. Thresholds that should change your choice: if measured recall on your corpus falls below ~0.5 on the edges your agent actually queries, enable the SCIP tier; if precision falls below ~0.9, tighten receiver resolution to fail-closed.

### Caveats
- Star counts and last-commit dates move quickly. Confirmed in this pass: sdsrss/code-graph-mcp 75 stars / 13 forks / 1,278 commits; brandyn-s/code-graph 0 stars / 603 commits; DeusData/codebase-memory-mcp roughly 43.2k stars / 3.5k forks. Not captured: codanna, GitNexus, sdl-mcp, codelens-engine star counts.
- The most-wanted artifact, edge-level precision/recall of a heuristic resolver against a SCIP or compiler oracle broken out per language and per tier, is largely non-public. brandyn-s/code-graph's measured-evidence.md and nodedb-lab/code2graph's scorecard both describe such numbers but could not be fetched; treat their existence as confirmed and their values as unverified.
- The 43.2k-star figure for codebase-memory-mcp is unusually high for a niche developer tool and its arXiv paper is a 10-page preprint (25 KB source); its headline numbers are answer-quality and token/tool-call ratios, not resolver precision, and should not be read as a compiler-oracle accuracy claim.
- GitNexus's PolyForm Noncommercial license and codelens-engine's license were taken from project materials/prior briefing and not re-verified against the LICENSE file in this pass.
- kyanosq/groundgraph and mbenhamd/codegraph could not be verified; the former did not appear in searches at all, and the latter's identity is inferred from a sibling repo with the same provenance-tagging approach.
