## Solution/Approach

### The one test

`tests/144_scm_lower.rs`, 375 -> ~200 lines, 21 `#[test]` fns -> 1 (`scm_lowering`).

ONE `.scm` query, 4 labelled patterns (utils) and 11 predicates on one capture,
run once against one fixture, compared to one committed snapshot at
`tests/fixtures/scm/lower.snap`. Snapshot mechanism copied from the repo's own
`tests/snapshot.rs:69`: on-disk `.snap` plus `UPDATE_SNAP=1 cargo test`.

The query:

```scheme
[(closure_expression)] @closure
[(function_item) (impl_item)] @scope
[(let_declaration)] @decl
[(field_expression)] @receiver

((call_expression
   function: (field_expression !arguments field: (field_identifier) @name)) @m
 (#inside? @m scope)  (#not-inside? @m closure)
 (#has? @m receiver)  (#not-has? @m closure)
 (#follows? @m decl)  (#not-precedes? @m decl)
 (#match? @m "contains") (#not-match? @m "is_empty")
 (#pattern? @m "$R.contains($A)")
 (#inside? @m scope receiver)
 (#has? @m receiver neighbor))
```

`matches: 1`, `["name.contains(\"ab\")"]`. The closure call and the generic are
each excluded by a different operator, so the conjunction is a real intersection.

The snapshot ends in three censuses computed by walking the lowered rule, so a
variant becoming reachable (or unreachable) is snapshot drift, never silence.

### The four refusals removed

| refusal | how it is now reached |
| --- | --- |
| `AstRule::Pattern` | new `#pattern? @m "<text>"` arm in `lower_predicate` |
| `StopBy::Rule` | third predicate argument: `#inside? @m scope receiver` |
| `stop_by: None` (immediate neighbour) | third argument spelled `neighbor` |
| `ScmLowerError::Parse` | DELETED; both sites depended on the compiled-in grammar, never on input |

Arity gate widened from `!= 2` to `!(2..=3).contains(&len)`.

### The defect the refusal was hiding

`StopBy::Rule` never serialized correctly. `relation()` did
`put(&mut inner, "stopBy", stop_by)`, which uses `StopBy`'s own derive; its
`Rule` arm holds an `AstRule` whose derive spells the VARIANT name, so the YAML
carried `Inside: {...}` where ast-grep reads `inside: {...}`, and
`from_yaml_string` answered `InvalidRule("Fail to parse yaml as RuleConfig")`.
Nothing could construct it, so nothing caught it. Fixed by matching both arms
and routing `Rule` through `rule_wire`.

## Key Insights

**A table of `Case` structs is the same as N tests.** First attempt at "one test"
produced a 26-entry `CASES` table driven by a loop. The user rejected it as the
same thing wearing a hat. The real answer is ONE query that uses every operator
simultaneously, so the conjunction itself is under test. That is also strictly
stronger: a table proves each operator alone, one query proves they compose.

**Sibling relations apply to the captured node, not to the pattern.** The maximal
query returned 0 rows until the capture moved from `@name` (the
`field_identifier`) to `@m` (the whole `call_expression`). A `field_identifier`'s
siblings live inside `field_expression` and are never adjacent to a
`let_declaration`, so `#follows? @m decl` could not hold. Bisecting predicate by
predicate found it; each alone gave n=0 for `follows` while the other seven gave
1..3.

**The unreachable variant was the broken one.** `StopBy::Rule` had a serialization
bug that had never fired because no input could construct the value. Removing the
refusal is what exposed it. Treat "UNREACHABLE" in a census as "untested", not as
"unused".

**Predicate argument flatness is a grammar fact, not just a runtime one.**
`tree-sitter`'s `QueryPredicateArg` is `Capture | String`, AND
`tree-sitter-tsquery`'s own `parameters` node accepts only
`capture | identifier | string`. Neither admits a nested rule. Recursion arrives
by name: an `identifier` argument resolves to a top-level `@`-labelled
definition, lowered to `AstRule::Matches(id)` plus a `utils` entry. The third
argument for `stopBy` uses the same mechanism.

**`ryi` lives in `crates/sprefa-extract` and that crate is its OWN workspace
root.** `cargo test -p sprefa-extract` from the repo root fails with `did not
match any packages`. Every cargo command runs from `crates/sprefa-extract`. The
gate is `cargo test --features cli`.

**A brief that names a new numbered test file must read the whole directory.**
Three briefs this session each picked its number from the file above it, and
`36_drain.rs` / `37_fact_matcher.rs` / `38_move_perf.rs` already held 36/37/38.
Highest in `tests/` is 143. The three new files are 144/145/146.

**One test in this suite is load-sensitive.**
`qualified_import_resolve_wall_grows_linearly_with_file_count`
(`tests/62_go_module_plane.rs`) asserts a wall-clock shape. It went red while
three cargo builds shared the machine and green alone. A wall-clock assertion in
a suite other agents run concurrently produces a red that looks like a
regression; it belongs behind a feature flag or a generous bound, and it is not
in the skill's known-red list where a reader would look.

**`cargo test` aborts remaining binaries on first failure.** A partial count reads
like a real one: run 1 reported `binaries 121 passed 661` out of ~184/~997. Every
gate run in this repo wants `--no-fail-fast`.

**Comment hook.** A `PostToolUse` hook rejects more than 2 consecutive comment
lines in new code: "Repo law: comments state only constraints the code cannot
show." Waiver is `@comment-ok: <reason>`.

## Open Questions

1. Should `#pattern?` exist at all? It admits ast-grep metavar text into a `.scm`
   file, which mixes two surface syntaxes in one document.
2. Is `neighbor` the right spelling for `stop_by: None`? It matches ast-grep's own
   `stopBy: neighbor`, but it arrives as a bare identifier in a slot that
   otherwise names a label, so `@neighbor` as a real label would shadow it. No
   test covers that collision.
3. `ScmLowerError::Parse` is gone. Is deleting a public enum variant acceptable
   here, or should it have stayed with a doc note that no input reaches it?
4. Does the lowering need a rail asserting every emitted `kind:` string exists in
   the target grammar's node-types? ast-grep matches nothing, silently, on a
   nonsense kind, and `.scm`'s own "Impossible pattern" check is gone on this path.
