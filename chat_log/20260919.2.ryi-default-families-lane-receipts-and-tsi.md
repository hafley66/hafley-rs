## Problem/Context

`ryi src/main.ts` prints 10852 JSONL lines for a 587-line file, 7571 of them
the parse tree, because `--family` defaults to the union of every option.

The reflex fix is a conditional, since 18+ extensions (sh, md, html, rb, lua,
css, java, c, cpp) have nothing but cst and a flat drop prints nothing.

The glm lane built a conditional, but per FILE rather than per language: it
extracts with `FamilyMask::ALL`, then prunes cst when any non-cst bundle
returned rows (`family.rs default_keeps_cst`, called at `ryi.rs:949`).

## Decisions

**User-set 2026-09-19: no conditional at all.** One default for every language,
`call,type,df`, cst always opt-in. The conditional was rejected twice, first as
per-file, then as per-language.

The reasoning that killed it: cst can carry shitty guesses. Every tree-sitter
grammar names its call nodes, and the python fixture's own cst output shows
`kind:"call"` with an `identifier` child and an `argument_list` sibling. So a
generic call-kind table mints call sites in any language with no front-end.
Those land in the existing `resolved_edge` / `unresolved` vocabulary, needing
no new record type and no new `ResolutionOrigin` variant.

When nothing answers, disclose HATEOAS style rather than print a parse tree or
nothing. The crate already carries this doctrine: `extract-graph-verb` states
that a state which cannot answer prints what it can plus the commands that
would answer it.

**User-set 2026-09-19: cross-language normalization is sprefa/dl8 territory,
not this crate's.**

**User-set 2026-09-18, still governing:** this crate is dl8's EDB producer.
Facts here, resolution RULES in dl8 as `.dl7` programs.

## Key Insights

**The `--lines` decoration rule generalizes per span, not per row.** The glm
lane declared `resolved_edge` a stop because no single line table decorates a
row spanning two files. True, and beside the point: `schema/1_facts.tsp:64-71`
pairs every span with its owning path, so `caller_site_*` decorates against
`caller_path` and `callee_*` against `callee_path`. Pushback closed it. The
stops it then named ARE real: `flow_edge` and `projectedge` own spans by
content digest (`from_blob`/`to_blob`) with no path in the row, and
`scip_signature_occurrence` offsets index signature text rather than a file.

**tsi already is the generic layer.** `src/tsi/{ingest,semantic,registry,sink,
types}.rs` plus a normalized vocabulary in `types.rs`:

| concept | normalized as | line |
| --- | --- | --- |
| product types | `TypeEntityKind::Struct` + `TypeEdgeKind::Field` | `:226,258` |
| sum types | `TypeEntityKind::Enum` + `TypeEdgeKind::Variant` | `:227,259` |
| generics | `TypeEdgeKind::{Generic,Param,Returns}` | `:261-263` |
| consts | `TypeEntityKind::Const` | `:233` |
| exports | `SpecifierKind::{Named,Default,Namespace,Reexport,ReexportModule,SideEffect}` | `:797-803` |
| scope | ABSENT as an entity, ad-hoc per language inside resolve | |
| visibility / pub | ABSENT | |

`TypeEntityKind::Ext(LangKind)` is the escape hatch that makes it survivable:
normalize what nine languages share, tag what one language has.

**Where cross-language normalization succeeds, per precedent.** Shallow
universal layers ship: LSP `SymbolKind`, tree-sitter `tags.scm`, SCIP symbol
strings. Narrow-and-deep ships when the narrow thing is genuinely shared:
scope graphs. CodeQL is deep and chose NOT to unify, one schema per language.
GitHub Semantic tried one cross-language AST via open unions and is archived.
Scope, exports and visibility fall on the shipping side. Product and sum types
and generics are where a Rust enum, a TS union, a Java sealed interface and a
Go interface stop being the same thing.

**Stack graphs are authored in TSG.** `tree-sitter-stack-graphs` builds them
from `.tsg` rule files, so per-language work is rules, not Rust. Resolution is
a path search where a reference resolves when the symbol stack starts with its
symbol and ends empty; it is a STACK because qualified names nest (`a.b()`
pushes `b` then `a`). Determining scope during ingest IS the input. It gives
name binding, never type inference, so `x.foo()` resolves only when `x`'s
binding was syntactically typed. That is the same wall as the untyped-receiver
decline law. `github/stack-graphs` was archived 2025-09-09, which is why
`lab-scopegraph-queries` is written as a from-scratch parrot.

**What the flash-review lane broke and fixed.** Row 8 replaced a `locals`
stack with `scope_lookup`, but `visit_variable_declarator`
(`ts_receivers.rs:462-503`) calls `scope_insert` BEFORE
`walk_variable_declarator`, while the deleted code inserted after. So
`const project = project()` self-shadowed. Fixed at `2b3ace3e` with
`initializing: Vec<(String, usize)>` keyed by scope FRAME INDEX so a nested
callable rebinding the same name still shadows.
