## Problem/Context

Last session's ladder said "buy the `.scm` pattern" without saying how. The
measurement this session: `.scm` cannot express ast-grep's relational model as
predicates, because `QueryPredicateArg` is `Capture(u32) | String(String)` and
the nvim grammar's `parameters` node accepts only `capture | identifier | string`.
A predicate argument is never a nested rule, in either the runtime or the grammar.

`.scm` nesting is strict direct-child and statically checked. Measured:

```
ryi query --lang rust --query '(function_item (field_expression ...))'
invalid query at row 1: Query error at 1:16. Impossible pattern:
```

The grammar forbids that parent/child pair, so the query is rejected before any
source is read. Spelling the full path `function_item > body: block >
call_expression > field_expression > field_identifier` works, and breaks the
moment the source nests one level deeper. `stopBy: end` does not break.

## Solution/Approach

`.scm` is surface syntax only. Parse it with a tree-sitter grammar, walk the CST,
emit `AstRule`, and let `ast_grep_core` evaluate. Zero matching operators written.

The recursion limit is answered by naming, not nesting: `parameters` accepts an
`identifier`, a top-level `definition` carries a `capture` label, so
`(#inside? @m local.scope)` lowers to `Matches("local.scope")` inside
`Inside{stop_by: End}` with `local.scope` as a `utils` entry. ast-grep resolves
the reference. Same shared-key mechanism `.tsg` used.

## Key Insights

**The lowering runs on real code, measured on `src/project.rs`, 108887 bytes.**

```
query                                hits  top names
plain: any field_identifier          1441  clone:63  path:63  map:51
OR: [] alternation                   4988  path:155  input:146  Some:120
parent: #inside? a fn, by name       1315  clone:63  path:61  map:51
parent: #inside? a closure            417  path:46  clone:42  to_string:30
NOT: #not-inside? a closure          1024  iter:46  map:39  collect:34
NOT: #not-match? leading underscore  3533  input:144  Some:120  cx:92
has: fn with a where clause             0
negated field: fn, no type params      87
```

417 + 1024 = 1441, an exact partition. That is `AstRule::Inside` and
`Not(Inside)` over the same corpus, at unbounded depth, from `.scm` text.

**The lowering drops what `AstRule` has no operator for.** Field selectors
(`function:`), supertypes, and quantifiers (`*` `+` `?`) are parsed and
discarded, keeping the node constraint underneath. `(_)` and `(MISSING x)` are
`ScmLowerError::Syntax`. Documented at `5_scm_lower.rs:33-40`.

**`.scm`'s static "Impossible pattern" check has no ast-grep equivalent.** A
nonsense `kind:` matches nothing, silently. A rail test asserting every emitted
kind string appears in the grammar's node-types is not written yet.

**The predicate leak dropped rows with no error and no count.** `matches_predicates`
applied every OTHER pattern's predicates to a predicate-free pattern's matches.
Measured through the real binary, two patterns and one predicate:

```
before: {"var":"needle","line":2}
after:  {"fn":"outer","line":1} {"var":"needle","line":2} {"fn":"other","line":6}
```

Cause: the borrowed pattern's predicate referenced a capture the match lacks,
`capture_texts` returned `[]`, `0 == 1` failed, match dropped. Every `locals.scm`
and `tags.scm` is multi-pattern, so this blocked the whole vendoring step. Fix
was deleting the second loop; the body collapsed to the fold.

brief listed 2 `SymbolSeat` sites in `rust_rename.rs` and told the lane to run
