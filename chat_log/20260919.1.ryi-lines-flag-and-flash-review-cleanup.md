## Key Insights

**The fast/slow model is one relation read three times.** Every run writes the
same two columns: a yes/no (the row lands in `resolved_edge` or in
`unresolved`) and a confidence (`resolution_origin`, 14 values,
`src/types.rs:1664`). `resolution_origin` is not functionally determined by
(caller, callee), which is what makes it a confidence column rather than a key.
Fast stamps the tree-sitter legs, slow stamps `checker`, the external indexer
stamps `scip`. Lane B's work was making the three joinable on (path, site span,
target blob, target span).

**blob and span.** blob is `ContentId::Blake3` of the file's bytes
(`types.rs:60-70`); span is `(start, end)` byte offsets inside it;
`ZERO_CONTENT_ID` is the no-target sentinel. Files are content-addressed, so a
path rename does not move a target.

**Why method rename without a spelled receiver is 0 deterministic.** The fast
lane is CST plus declared-type tables with no inference. For `v.push(x)` the
receiver's type is not a CST fact, so the name is the only discriminator: 155
`push` sites share it, 7 are the target. Rewriting on name corrupts 148 sites.
`rust_rename.rs` emits `RenameStop`; the slow lane answers that class.

**callee_start differs per language.** rust: `def_span(.., f.sig.ident.span(),
f.block.span())` at `rust.rs:1547`, and `def_span` at `:1502-1515` uses its
FIRST argument for start, so rust's is the IDENT. A bodyless trait method takes
`m.sig.span()` as the end. kotlin: `node_span(child)` over the whole
`function_declaration` at `kotlin.rs:169`, so kotlin's is the `fun` KEYWORD.
Do not share a helper across the two; that would hide the divergence.

**The `--lines` decoration rule generalizes per span, not per row.** The glm
lane first declared `resolved_edge` a stop because no single line table
decorates a row spanning two files. True, and beside the point:
`schema/1_facts.tsp:64-71` pairs every span with its owning path field, so
`caller_site_*` decorates against `caller_path` and `callee_*` against
`callee_path`. Pushing back closed it. The residual stops it then named ARE
real: `flow_edge` and `projectedge` own spans by content digest
(`from_blob`/`to_blob`) with no path in the row, and
`scip_signature_occurrence` offsets index signature text rather than a file.

**A regression the sonnet lane introduced and then fixed.** Row 8 replaced a
`locals` stack with `scope_lookup`. But `visit_variable_declarator`
(`ts_receivers.rs:462-503`) calls `scope_insert` BEFORE
`walk_variable_declarator`, while the deleted `locals` insert ran after, with a
comment saying a binding owns its name only after its initializer. Result:
`const project = project()` self-shadowed and every name-match leg declined.
Only a self-named initializer reaches it, so the suite stayed green. Fixed at
`2b3ace3e` with `initializing: Vec<(String, usize)>` keyed by scope FRAME INDEX
so a nested callable rebinding the same name still shadows correctly.

**The `59_rust_scip_macros` failure was environmental and pre-existing.**
rust-analyzer exits 1 because the scip stage copies the fixture into a temp
repo under `crates/sprefa-extract/` and cargo reads it as a member of a
workspace that does not list it. Fixed by prepending `[workspace]` to
`tests/fixtures/rust_findings/scip_macros/Cargo.toml`, matching what
`rust_findings/checker/Cargo.toml` already did. 1 passed / 2 failed became 3
passed / 0 failed. Four other fixture manifests still lack the table
(`packages/broken`, `rust_move/{basic,relocate,visibility}`); none fail and
`packages/broken` looks deliberately broken.

mid-session, to `docs/boop-types-and-store-audit` and then to
`feat/observe-chrome-and-counts`. One merge landed on the wrong branch before I
noticed. Check `git branch --show-current` before every write there, and prefer
