## Problem/Context

Two structural problems surfaced and both are now filed.

**Capability is not declared where it matters.** Fourteen traits carry the
language seams. Thirteen declare capability as static data: `RESOLVE_ARMS`
(`project.rs:1703`), `rehomes()` (`lang/mod.rs:141`), `renames()`
(`lang/mod.rs:185`), `INDEXERS` (`scip_ensure.rs:62`). One does not:
`sources()` (`lang/mod.rs:117`) is a bare list and `Source::extract` returns
five `Option<FamilyBundle<_>>` decided at runtime.

The cause is trait-object erasure. The roster holds `&'static dyn Source`,
which carries only `Source`'s vtable, so nothing can ask whether the concrete
type also implements `Resolve<CallF>`. Rust has no reflection and cannot
enumerate impls, so every seam re-declares membership by hand.
`tests/1_resolve_cli.rs:127-128` states the resulting hole verbatim: "What it
does not catch: a row that declares None while an impl exists."

**Neither mode can answer a basic question.** `ryi --family call` over the
crate's own 101 files gives 24873 sites and 195 `contains` calls, with no way
to separate `str::contains` from `Vec::contains`. The SCIP run answers it in
principle: rust-analyzer 34.6s, `index.scip` 12.3 MB holding 678 `contains().`
occurrences and 67165 `core`/`std`/`alloc` symbol mentions. All 79637
symbol-bearing output fields are `sprefa-extract`, so ingestion drops every
external symbol.

## Solution/Approach

The ladder above tree-sitter, with each rung's verdict measured rather than
assumed:

| rung | verdict |
| --- | --- |
| typed wrappers (`type-sitter`, `treesitter-types`, `tss`) | candidate, not adopted; ids are grammar-relative so lane 2 resolved them at runtime instead |
| ast-grep | keep, it is the grammar bundle and the rewrite layer |
| `.scm` queries | **buy the pattern**; Zed ships 9+ files per language, Helix 7, nvim-treesitter's primary GitHub language is "Tree-sitter Query" |
| `tags.scm` / `locals.scm` conventions | vendor from Helix, open licensed |
| scip-syntax | **build**, no upstream survives, `sourcegraph/sourcegraph` is 404 |
| `.tsg` | **skip**, 2 crates.io reverse deps (both from stack-graphs), 1377 lines for one language |
| stack-graphs | archived 2025-09-09, read as spec |
| SCIP | already ingested, now under the `scip-code` org |

`.scm` has zero relational operators and `tree-sitter#880` has been open since
2021-01-13. The escape hatch is that the C library evaluates NO predicates:
`query.c`'s `ts_query__parse_predicate` accepts any identifier ending in `?` or
`!` generically, and the Rust binding hands everything it does not itself
evaluate to `general_predicates()`. So `#inside?`, `#has?`, `#precedes?`,
`#follows?` get implemented in Rust, re-infusing ast-grep's relational
vocabulary with no fork.

## Key Insights

**The commit contract fixes the receipt problem in prose.** Lane 2's brief
opened with a COMMIT CONTRACT section demanding a commit per phase plus
`Boop-Check: <command> -> <result>`. Boop delivers wip commits through the
parent's door, so each arrived as a status line. Five phases in 18 minutes,
five receipts, zero silent claims, against four prior lanes that all reported
`rc=0` with nothing. `lane-verify-receipt` still belongs, because prose is not
structure.

**Aider is the only surveyed tool that ranks, and its graph is file-level.**
`repomap.py:470` builds `nx.MultiDiGraph()` keyed by filename, one edge per
identifier referenced in one file and defined in another, weight
`mul * sqrt(num_refs)` with multipliers (10x chat-mentioned, 10x long name,
0.1x leading underscore, 0.1x more than 5 definers, 50x referencer open in
chat), then `nx.pagerank` at `:525` with personalization mass on chat-open
files. Budget is a binary search over ranked-tag count against a token target.

**`ryi fast` already emits more structure than any of them**: symbol-level
edges with a resolution origin. What it lacks is everything after extraction:
ranking, token budgeting, an outline mode, and sub-file invalidation. Zed is
the only tool below file granularity, via `tree_sitter::InputEdit` from buffer
edit history (`syntax_map.rs:381,500,513`).

**Nobody does type inference or dataflow with tree-sitter.** SCIP's precision
comes from delegating to each language's real compiler, which is the existing
subprocess seam. Nobody normalizes multiple languages at the AST level either;
the one-IR pattern lives at the symbol level (SCIP, Kythe, Glean), and
`github/semantic` tried the AST level and is stale since 2025-04-01. That
validates where `src/tsi/types.rs` sits.

**What TSG actually was.** Stanzas, each a tree-sitter query plus a statement
block. Two node kinds: syntax nodes (input CST) and graph nodes (output). Its
real mechanism is variables hung on syntax nodes, so a stanza matching
`(module)` creates `@node.before_scope` and a stanza matching
`(function_definition (block) @block)` reads `@block.before_scope` off the same
syntax node. They meet through a shared key, never through code. That is how it
fakes the relations `.scm` cannot express.

**Two `.scm` hazards that fail silently.** `api.h`: an exceeded match limit
"silently drops the earliest-starting in-progress match"; Zed set its limit to
64 and carries `zed-industries/zed#22042` for silent under-highlighting. And a
`*`/`+` capture binds multiple nodes within ONE match, so `matches()` groups
them and `captures()` destroys the grouping.

**Kotlin's real state.** Full parity through phase 1 and resolution (cst, type,
call, df planes; call, types and drops resolve arms; module and receiver
planes). Absent above that: no checker-tier feature, no semantic TSI rows, no
SCIP ratchet in `golden_parity.rs`, no `RATCHET.tsv` rows. `scip-java` is wired
at `scip_ensure.rs:91-97` but `JAVA_SPEC` is `Fallback::None` while ts has
`Npx` and go has `GoRun`, so kotlin is the only language with no toolchain-free
path. No JDK, coursier, scip-java or kotlinc on this machine.
