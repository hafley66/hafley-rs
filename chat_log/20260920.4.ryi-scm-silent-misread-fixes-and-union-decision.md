## Problem/Context

Three bugs, all the same shape: the code read one thing as another and said
nothing.

| bug | mechanism | why nothing caught it |
| --- | --- | --- |
| `stopBy` mode stole a label | the literal `"neighbor"` check ran BEFORE the label lookup, so a real `@neighbor` top-level pattern was read as the walk mode and its rule entered `utils` unreferenced | ast-grep accepts a dead `utils` entry; the query just meant something else |
| bogus `kind:` matched nothing | `.scm` through `Query::new` gets a static "Impossible pattern" refusal from the tree-sitter query compiler; the ast-grep path has no equivalent | a kind no grammar spells is a rule that matches zero nodes, which looks like a true negative |
| `query_language` listed 9 languages by hand | `RyiLang::parse_name` already knew 28; the hand list had rust/ts/tsx/js/go/kotlin + md/md_inline/html | `ryi query --lang ruby` reported "unknown lang 'ruby'" with the ruby grammar sitting in the ast-grep bundle |

## Solution/Approach

**Bug 1, `src/lang/5_scm_lower.rs`.** A third predicate argument is now typed by
its CST node kind, not by its text:

```rust
let stop_by = match parameters.get(2) {
    None => Some(StopBy::End("end".into())),
    Some(node) if node.kind() == "string" => match string_argument(*node, source)?.as_str() {
        "neighbor" => None,
        "end" => Some(StopBy::End("end".into())),
        other => return Err(ScmLowerError::UnknownStopBy(other.to_string())),
    },
    Some(node) => Some(StopBy::Rule(Box::new(AstRule::Matches(
        reference_argument(*node, source, labels)?,
    )))),
};
```

An `identifier` is ALWAYS a label; a `string` is always the mode. New variant
`ScmLowerError::UnknownStopBy(String)`. `"end"` became expressible as a
by-product.

**Bug 2, `src/lang/1_ast_rule.rs`.** New `unknown_kind(&AstRule, RyiLang) ->
Option<AstRuleError>` recurses the rule tree and BOTH `stopBy` arms, checking each
`Kind` against the grammar's own table:

```rust
use ast_grep_core::tree_sitter::LanguageExt;   // this is the trait with get_ts_language
let grammar = language.get_ts_language();
let spelled = |name: &str| {
    (0..grammar.node_kind_count())
        .filter_map(|id| grammar.node_kind_for_id(id as u16))
        .any(|kind| kind == name)
};
```

Called from `query_ast_rule_with_content` over `request.rule` then every
`request.utils` entry, before the YAML is built. New variant
`AstRuleError::UnknownKind { kind: String, language: String }`.

**Bug 3, `src/lang/2_source_query.rs`.** The 9-arm match became:

```rust
fn query_language(name: &str) -> Result<tree_sitter::Language, String> {
    crate::lang::extract_lang::RyiLang::parse_name(name)
        .map(|lang| lang.get_ts_language())
        .ok_or_else(|| format!("unknown lang '{name}'"))
}
```

Dropped the then-dead `use std::str::FromStr` and `SupportLang` imports.

## Key Insights

**The three bugs share one shape: a check whose order or absence changed meaning
without producing a diagnostic.** Precedence (literal before lookup), a missing
validation (no kind table consulted), and a hand-maintained list drifting from
the real one. None was a crash, none was a wrong answer that looked wrong.

**`AstRuleError::UnknownKind` names the language, and that matters.** The same
kind string is valid under one grammar and absent under another. The test pins
five: `Rust`, `TypeScript`, `Python`, `prolog`, `gdscript`. Note the casing is
inconsistent (`SupportLang` Display gives `Rust`/`TypeScript`, the non-Sg arms of
`RyiLang::name()` give lowercase `prolog`/`gdscript`/`commonlisp`). That crosses
the cross-system casing rule in AGENTS.md and is worth a look.

**`get_ts_language` lives on `ast_grep_core::tree_sitter::LanguageExt`,** not on
`ast_grep_core::Language`. `2_source_query.rs` reaches it via
`ast_grep_language::LanguageExt`. Getting this wrong is a one-line E0599.

**Two failing tests were signal, not noise.** `9_query_cli` used `ruby` as its
"unknown language" case: ruby has a grammar in the ast-grep bundle, so that test
was encoding the bug. `30_ast_rule` asserted `InvalidRule` for a bogus kind, which
was the YAML layer failing downstream rather than the kind being refused. Both
UPDATED in place, neither deleted.

**Two of the four reds were self-inflicted by `rm -rf`.** `examples/` already
held 4 tracked files (`cpg_import.rs`, `gen_scip_sidecar.rs`, `rss_probe.rs`,
`typegraph_d2.rs`); `rm -rf examples` took all of them and `15_typegraph_d2.rs`
failed with "no example target named `typegraph_d2`". Restored with
`git checkout origin/main -- crates/sprefa-extract/examples/`.

## Open Questions

1. The `UnknownKind` language casing is mixed (`Rust` vs `prolog`). Normalize
   `RyiLang::name()`, or leave it because the `Sg` arms must keep ast-grep's own
   spelling for the YAML `language:` field?
2. Should `AstRule::Pattern` strings get the same lower-time validation `Kind` now
   has? A malformed pattern is silent today, and validating it means handing the
   text to ast-grep during lowering.
3. Does `#pattern?` belong in `.scm` at all? It admits target-language source text
   into a file that is otherwise S-expressions. It is the only operator that can
   require two holes be the same expression (`$R.contains($R)`), which nothing
   else in the lowering reaches.
4. The two questions still open in session 20260920.3 about `just test`: which
   boundaries define an e2e tier, and rename-all-185 vs classify-by-grep.
