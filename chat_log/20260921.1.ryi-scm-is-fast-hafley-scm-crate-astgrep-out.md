## Problem/Context

- Three query engines existed by construction of my own no-touch briefs: `5_scm_lower.rs` (scm->ast-grep, one node per match, `FocusConflict` on two captures), `2_source_query.rs` (native, `sprefa-*` predicates only), `6_scm_family.rs`/`7_scm_rows.rs` (native, bypassing the lowering). ast-grep is four engines in sprefa-extract: lowering, parser+CST projection (`astgrep.rs`, rust/ts/go/kotlin parse through `AstGrepParser`), `--ast-pattern`, and the edit bridge into soopy (`drain.rs`, `fact.rs`, `BoundEdit`).
- Owner decision: ast-grep is removed. One native engine with host predicates. Soopy stays the edit engine. Latest ast-grep 0.45.3 still one node per match; repo pins 0.38.7.
- Probe (my own, ast-grep 0.38.7, `a + b`): `has: {field: left/right}` gives L=a R=b; plain `has` gives L=a R=a; `pattern: $L + $R` gives L=a R=b. So ast-grep CAN pin two nodes via `field:`; `lower_scm` never emitted metavars. Removal reason is the four-engine sprawl, not library inability.
- Survey (`plans/2026-09-21-scm-tooling-survey.md`): nobody ships relation predicates as a library; tree-sitter C evaluates none, hands `general_predicates()` back. Adopt `tree-sitter-tags` 0.27 for def/ref, copy `tree-sitter-highlight` `LocalScope`, use Neovim spellings (`has-ancestor? has-parent? contains?`, `not-`/`any-` prefixes). stack-graphs, scip-syntax, tree-sitter-graph archived/stale.
- Audit (`plans/2026-09-21-scm-replaceable-audit.md`): walk 10,086 + walk-plus 1,398 of 36,993 fn lines (31%); net reachable saving ~4,000; but `call_defs_in_items` runs on syn and threads `under_cfg`, so audit mis-bucketed it.

## Solution/Approach

`crates/hafley_scm` (workspace member, path dep of sprefa-extract):
- `types/`: `QueryExt { user, kinds, predicates, names }`, `Predicate { pattern, capture, kind, walk, stop, negated }`, `Walk { Ancestor, Descendant }` (TODO earmarked: Precedes, Follows, NthChild, ByteRange, Parent), `Stop { Neighbor, End }` (TODO `Rule(u16)`), `MatchArena { files, spans, rows }` one per run, `MatchRow { file, pattern, spans: Range<u32> }`, `CapturedSpan { name, bytes }`, `QueryExtError { Parse, UnknownOperator, Arity, MatchLimit }`. Earmarked TODO comment: `any-`, `#set!`, `field:`, `pattern:` $META, `fix:`, YAML, explain.
- pipeline folders per `lib.rs` doc comments: `split_predicates_into_kind_queries/` (ts_read_general_predicates, parse_predicate, mint_kind_query_text), `build_query_ext/` (ts_query_new_per_kind, intern_names), `run_over_file_tree/` (ts_kind_cursors_into_sorted_ids, ts_user_cursor_into_candidates, test_predicates_per_candidate, append_to_match_arena, ts_match_limit_check), `walk/` (ts_ancestor, ts_descendant, dispatch).
- Mechanism: tree-sitter runs the user `.scm` unchanged; `general_predicates()` yields our operators; one minted `(kind) @_` query per distinct kind arg; kind node ids sorted; per candidate walk parent/children and `binary_search`; keep iff holds != negated. 1 query in, 1+N run, one filtered set out. No text surgery on `.scm`.
- Laws (in `NAMING.md` and to go in `AGENTS.md`): rows carry `Range<u32>`, no String/&str/lifetime; compile once per language; one arena per run; sorted Vec + binary_search; iterative walks; per-match tree-sitter call is N+1; match limit is an error; unknown operator is an error; `#set!` kept.
- Proposed syn feature: `hafley_scm` feature `rust_syn` default on, gated `src/lang/rust/syn_macro_expansion_defs.rs`, `syn_const_init_defs.rs`, `syn_cfg_scope.rs`; `run_with_syn_supplement` appends those rows after the `.scm` pass; expander moves from `sprefa-extract/src/lang/rust_mbe.rs`.
- Removal lane (`plans/2026-09-21-remove-astgrep-native-scm.md`): 8 phases, P0 corpus with pinned counts first, P1 16 grammar crates direct, P2 engine, P3 `ryi query`, P4 fast families, P5 native parser+CST for rust/ts/go/kotlin, P6 crate-owned edit type, P7 delete `5_scm_lower.rs` 647 + `1_ast_rule.rs` 672 + `astgrep.rs` 581 + tests 30/144 + example + 4 deps, P8 docs. Owner-settled: drop `#pattern?`, drop `--ast-pattern`, drop YAML `fix`.
- Brief rails (agreed): allowed new names listed, done = named command prints named count, spellings fixed, decisions closed before spawn, no "as you go", PR per phase, read crate with `ryi query`/`ryi fast`.

## Key Insights

- scm IS fast. Fast and slow are ingest types filling the same rows; verbs read facts and call one per-language trait (`Cleave`: `edit_export`, `edit_import`, `spell_module`, at `src/lang/<lang>/cleave.rs`) for text. Two languages in one file is a leak.
- ast-grep = querySelectorAll (one node out); tree-sitter query = tuple query (N captures). Family rows need tuples.
- The one-node loss was local (`lower_definition` focus step; `lower_node` never emits metavars), and `field:` exists on `has`/`inside`; still removing for sprawl.
- Cleave never silently widens visibility or adds `mod`/barrel; plan rows, stop by default, `--widen`.
- Receipts: `ryi rename` renamed `Mutate`->`Cleave` (0 abstains) and `ryi move` moved both impl files with `--verify`; gaps: `rename` lacks `--verify`, skips `///` prose.
- Naming rules distilled in `crates/hafley_scm/NAMING.md`: dir carries its noun once, children add only; verb files end in their object; nouns carry their object; `ts_` prefix for tree-sitter calls; one type per file under `types/`; names from library word, owner word, or physical object only, else `TODO_NAME`; single-word files refused; read-aloud test.
