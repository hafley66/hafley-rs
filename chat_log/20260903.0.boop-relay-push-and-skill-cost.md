## Problem/Context
- A 4-node relay test (codex-414 -> claude-415 -> codex-416 -> claude-417 -> codex-414) as boop tui panes in one cwd showed two sibling panes collapsing onto one harness session: both codex routes bound 01a0653d-...0436, both claude routes bound one claude session, and node 3 executed node 1's completion instruction. Root cause: newest_opened_session took max(observed_ms) among new same-cwd sessions, so simultaneously launched wrappers double-bound the newest session.
- Lane create one-shot lanes exit rc=0 after their brief turn, so persistent relay siblings need boop tui panes.
- The user's real pain: beeps to routes that could not yet take a row parked in the mailbox forever ("tired of asking my agents to read mail"). Bare codex outside tmux registered a route with no harness, no cwd, no session (codex-tsi), which no rung could reach.
- Skill cost analysis had to cost zero LLM tokens: everything derived from already-ingested transcripts in ~/.agent/boop.db.

## Solution/Approach
- Binding (ff9ff16): opened_session/newest_opened_session take the wrapper's pane; a candidate whose tmux_pane matches wins outright; registry sessions another live pane carries are excluded; a registry-derived bind takes an exclusive tui-claim-<session> marker in the mail dir so same-tick wrappers take two sessions, one each.
- Mail push (45e0cf2): `agent register` takes --harness/--cwd and the shell wrappers pass both; boop-proc/deliver.rs gained claim_open_session, prune_claims (24h TTL), claimed_sessions, bind_route_session (binds only when exactly one unclaimed root candidate exists in cwd; zero or several bind nothing), drain_route_held_mail and drain_all_held_mail. Drainers run on the tui wrapper's 5s tick and on every sync-carrying command (sync_before_local_command -> drain_all_held_mail_best_effort). A row the door takes is acked via bus::ack_messages so reads and waits never replay it. held_messages excludes rows whose latest transition is accepted-by-harness.
- bus.rs gained write_route/route_to_json (registry.json CAS write path usable from boop-proc) and held_messages(store, route).
- Skill cost (SQL only, no schema change): windows = activation turn to next real user turn, excluding user-role echoes ("Base directory for this skill%", "<command-%", "Caveat:%" — 1,088 such rows); cost = sum agent_usage over window turns, coalesce(cost_usd_recorded, tokens x model_price rates); chart rollup groups by skill x model x date(ts/1000).

## Key Insights
- boop tui derives route names from the tmux pane (codex-413 style) and rejects --name.
- codex's state_5.sqlite threads table carries no pane or pid; a TUI's thread row appears only after its first turn, so door liveness starts there.
- The claude door reads per-pid registry files under ~/.claude/sessions and carries pane ids, so claude binds pane-exact; codex binding is registry-derived and needs the claim marker.
- In SQLite, integer >= strftime('%s', ...) is always false (text ordering); cast the strftime result.
- agent_turn roles: tool results are role 'tool'; skill preambles and command echoes are role 'user' and must be excluded from window boundaries.
- ccusage reads the same local transcripts and prices via LiteLLM rates; the skill-activation window attribution is the part no comparable build does.
- Eyeball token cost = chars/4 of SKILL.md (worst case); measured marginal from agent_usage delta runs lower after caching (d2-authoring: 5,595 eyeball vs 1,023 felt).
