## Key Insights

**The crate's capability gap is one seam, not a missing architecture.** Fourteen
traits carry the language seams (`types.rs:173, 1843, 1862, 1874, 2357, 2661,
2712, 2780, 2962`). Thirteen declare capability as static data: `RESOLVE_ARMS`
(`project.rs:1703`), `rehomes()` (`lang/mod.rs:141`), `renames()`
(`lang/mod.rs:185`), `INDEXERS` (`scip_ensure.rs:62`). One does not:
`sources()` (`lang/mod.rs:117`) is a bare list, and `Source::extract` returns
five `Option<FamilyBundle<_>>` decided at runtime.

The reason every table exists: the roster holds `&'static dyn Source`, and a
trait object erases every trait but the one it names. Rust cannot ask a
`dyn Source` whether the concrete type also implements `Resolve<CallF>`, and
cannot enumerate impls. `tests/1_resolve_cli.rs:127-128` states the resulting
hole verbatim: "What it does not catch: a row that declares None while an impl
exists."

**Tree-sitter kind ids are grammar-relative, so no const and no match.**
`Node::kind_id() -> u16` and `Language::kind_to_id(&str) -> u16` exist
(`ast-grep-core-0.38.7/src/node.rs:146`, `language.rs:44`), but `identifier` is
a different number in every grammar. Eleven grammars load in one binary, so ids
must be resolved once per parsed root. A real `match` needs per-grammar
generated enums: `type-sitter` (vendoring required), `treesitter-types`
(pre-generated per-language crates, no vendoring), `tss`/`tss-rust` (kind enum
only, 277 and 354 downloads).

**`.scm` has no relational operators, and the extension path is host
predicates.** `tree-sitter#880` "Specify descendant or ancestor in query" has
been open since 2021-01-13. `inside`, `has`, `not` over a subpattern,
`precedes`/`follows` at distance, cross-match constraints, arithmetic and
recursion are all absent.

But `query.c`'s `ts_query__parse_predicate` parses any identifier ending in `?`
or `!` generically, with no special-casing, and `api.h` exposes only
`ts_query_predicates_for_pattern`. The C library evaluates NOTHING. Hosts add
their own: Neovim ships `#has-parent?`, `#has-ancestor?`, `#contains?`,
`#lua-match?` in `runtime/lua/vim/treesitter/query.lua`; Helix ships
`#same-line?`, `#one-line?`, `#not-kind-eq?`. The Rust binding auto-evaluates
only the text family and hands everything else to `general_predicates()`.

So ast-grep's relational vocabulary can be re-infused into `.scm` in Rust, with
no fork and no dependency on #880.

**Two `.scm` hazards that fail silently.** `api.h`: an exceeded match limit
"silently drops the earliest-starting in-progress match"; Zed set its limit to
64 and carries `zed-industries/zed#22042` for silent under-highlighting. And a
`*`/`+` capture binds multiple nodes WITHIN one match, so `matches()` groups
them and `captures()` destroys the grouping; maintainers call mixing the two a
correctness defect.

**What TSG actually was.** A `.tsg` file is a sequence of stanzas, each a
tree-sitter query plus a block of statements. Two node kinds: syntax nodes
(input CST) and graph nodes (output). Its real mechanism is variables attached
to syntax nodes (`@node.after_scope`), so a stanza matching one pattern and a
stanza matching another can meet at the same syntax node and wire graph nodes
together. That is how it reconstructs relations `.scm` cannot express: through
shared keys, not through the query.

**Stack graphs, concretely.** Every statement and block gets `before_scope` and
`after_scope` graph nodes chained through the file; definitions become
`pop_symbol` nodes and references `push_symbol` nodes; resolution is a path
search carrying a symbol stack, complete when the stack empties. The stack
exists because qualified names nest: `a.b()` pushes `b` then `a`.

**`.scm` is the adopted per-language extension point.** Zed ships 9+ query files
per language and extended the pattern into debugger and task-runner config;
Helix ships 7; nvim-treesitter's primary GitHub language is "Tree-sitter Query".
GitHub-wide: `highlights.scm` 48768 files, `locals.scm` 14688, `tags.scm` 7088.
ast-grep and semgrep deliberately do NOT use `.scm`; both ship their own rule
DSL. Aider does not author `.scm` either, it vendors from
`tree-sitter-language-pack`.

**Nobody normalizes multiple languages at the AST level.** The one-IR pattern
lives at the symbol and graph level: SCIP, LSIF, Kythe (2155 stars, active),
Glean (1408, active). `github/semantic` tried it at the AST level, 9046 stars,
stale since 2025-04-01. This validates `src/tsi/types.rs` being where it is.

**SCIP moved orgs.** `sourcegraph/sourcegraph` is 404. `scip-code/scip` (807),
`scip-java` (134), `scip-go` (71), `scip-rust` (11), all Apache-2.0 and active.
No `scip-syntax` in the new org; `sourcegraph/scip-semantic` archived
2023-03-16. `scip-code/scip-rust` is a shell wrapper around
`rust-analyzer scip`, nothing to adopt.

**ast-grep over raw tree-sitter, what it adds.** Pattern by example with
metavariables; five strictness modes (`Cst, Smart, Ast, Relaxed, Signature`,
`match_tree/strictness.rs:9-15`); a relational rule algebra in YAML (`pattern,
kind, regex, inside, has, precedes, follows, all, any, not`,
`ast-grep-config/src/rule/mod.rs:48-92`); rewriting via `fixer.rs` and
`transform/`, which tree-sitter has no layer for; and grammar bundling.
It cannot feed `.tsg` or stack-graphs, which consume `.scm` specifically.
Amusing: `ast-grep-core/src/match_tree/strictness.rs:30` does
`kind.contains("comment")`, the same defect lane 2 removed from `kotlin.rs:343`.

## Traps

**`rc=0` still is not evidence.** Both lanes this session were verified by hand
before merging. Lane 2 attached receipts voluntarily because its brief demanded
them per commit; that is prose, not structure. `lane-verify-receipt` stands.

**A piped gate hides its exit code.** `cargo test ... | tail -80` reported exit
0 while the build was dying. Write to a file and check cargo's own status.

**A retiring lane deletes its incremental cache.** The first hand-run gate died
on `target/debug/incremental` disappearing mid-build. Use
`CARGO_INCREMENTAL=0` when verifying a retired lane's worktree.

**Monitor filters must match failures only.** Arming a Monitor on `^test result`
turned 184 passing lines into ~30 forced turns. Match `FAILED|panicked|^error`
and the final summary, never the passing rows.

implausible numbers: `Graphify-Labs/graphify` 119672 stars created 2026-04-03,
