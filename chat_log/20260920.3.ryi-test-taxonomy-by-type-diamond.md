## Problem/Context

**Why 140 files read as e2e.** 129 of 179 reference `env!("CARGO_BIN_EXE_ryi")`
and shell out to the binary to assert a fact about extraction. They cross a
process boundary for convenience, not because the boundary is the subject. Most
are integ tests wearing an e2e costume. Turning the inverted pyramid into a
diamond means converting roughly 100 of them to library calls, which is the real
work behind this request.

**Why the existing `just test` cannot serve.** The recipe is
`cargo nextest run --workspace {{ARGS}}` and `crates/sprefa-extract` declares its
own `[workspace]` (Cargo.toml:23) with its own `Cargo.lock`, so `--workspace` at
the repo root reaches NONE of its 179 test binaries. CI never runs them either.

## Solution/Approach

Reproduce the classifier before anything else. This exact probe produced the
numbers above, run from the repo root against `origin/main`:

```sh
git ls-tree -r --name-only origin/main crates/sprefa-extract/tests/ \
  | grep '\.rs$' | awk -F/ 'NF==4' > /tmp/top.txt
for f in $(cat /tmp/top.txt); do
  c=$(git show origin/main:$f)
  echo "$(basename $f)|$(echo "$c"|grep -c CARGO_BIN_EXE_ryi)|$(echo "$c"|grep -cE 'Command::new\("git"\)|soopy::')|$(echo "$c"|grep -cE 'scip-typescript|scip-go|scip-java|npx|rust-analyzer|Command::new\("node"\)|Command::new\("swipl"\)|gradle')|$(echo "$c"|grep -cE 'sqlite|Connection::open')|$(echo "$c"|grep -cE 'tempfile|TempDir|fs::write|fs::create_dir')"
done > /tmp/t2.txt
```

Fields are `name|proc|git|tool|store|fs`. Classification rule used:
`proc||tool -> e2e` (tier = count of distinct boundaries), else
`git||store||fs -> integ`, else `unit`.

`awk -F/ 'NF==4'` is load-critical: without it the glob picks up ~205
`tests/fixtures/**/*.rs` files and the total reads 390 instead of 185.

Proposed boundary set for the n-choose-k tier (NOT yet agreed):

| boundary | what crosses it |
| --- | --- |
| `proc` | the `ryi` binary as a subprocess |
| `git` | soopy, real git objects and blob ids |
| `store` | SQLite, `--sqlite` |
| `indexer` | `scip-typescript` / `scip-go` / `scip-java` |
| `checker` | rust-analyzer / `tsc` / go toolchain |
| `fs` | a real temp tree |

Proposed naming, suffix appended after the existing numeric prefix so both the
author-driven ordering and the type survive:

```
0_subject_unit.rs
10_source_tree_integ.rs
8_scip_families_e2e.k2.rs
```

Proposed surface:

just test unit -- -E 'test(scm)'

## Key Insights

**`ryi` is unreachable from the root workspace.** Root `Cargo.toml` has
`exclude = ["crates/ghcache", "crates/ghcache-client", "crates/sprefa-extract"]`,
and each of those declares its own `[workspace]`. The exclusions exist because
ghcache uses `sqlx` and boop uses `rusqlite`; one lockfile cannot hold two
`libsqlite3-sys`. Each standalone root declares `[workspace]` itself so a git
worktree under `.claude/worktrees/` does not walk up past the parent's `exclude`
(railed by `tests/112_build_metadata.rs`). Correct reach:
`cargo test --manifest-path crates/sprefa-extract/Cargo.toml --features cli`.

**`--features cli` is mandatory, not optional.** There is no `default` feature.
`[[bin]] ryi` has `required-features = ["cli"]`, and 129 of 179 test files
reference `env!("CARGO_BIN_EXE_ryi")`. Without `cli` the binary is not built, the
env var does not exist, and those files fail to COMPILE. `AGENTS.md:96` states
the gate is `cargo test --features cli`.

## Open Questions

1. **Which boundaries define the e2e n-choose-k tier?** Six were proposed above.
   `fs` is the loosest (a temp tree is arguably integ baseline, and it is what
   pushes many files from k=1 to k=2). `store` is in-process SQLite, so a
   `--sqlite` test may be integ. Dropping both leaves 4 truly-external
   boundaries: `proc`, `git`, `indexer`, `checker`. Smaller set means more files
   fall to integ, which is the direction the diamond wants.
2. **Rename now or classify by grep?** Three shapes: (a) recipe reads the live
   grep classifier, zero renames, suffixes added opportunistically; (b) rename all
   185 in one mechanical pass so the suffix is the source of truth, at the cost of
   staling every `TASKS/*.BRIEF.md` and doc that names a test file; (c) rename,
   then a second pass converting ~100 spawn-the-binary tests into library-call
   integ tests, which is the only option that actually produces the diamond.
3. Does `just test` stay `ryi`-only, or does the same suffix convention get
   applied to the other 14 crates later? The suffix is language-agnostic by
   design, so the convention generalizes even if the recipe does not.
4. Do the two orphan suites (`2_gen.test.mjs`, `tmux-leak-rail.sh`) get wired into
   this command, or is that out of scope for a `ryi`-only recipe? The mjs one
   lives under `crates/sprefa-extract/schema/`, so it is arguably in scope.
