- boop seams: `Harness` trait facets (ingest/read_from, control: spawn/send/stop/open_channel/preview_command/one_shot); `Registry::discover()/by_id`; `lane::harness_for_model` (model spelling -> harness id; `x/y` path -> opencode; banned plan families refused); `Store::turn_rows(TurnQuery{since})`.
- User doctrine hammered this session: the pipe is a boop CORE feature; never name a harness inside boop code; traits everywhere; the bash script semantics are the spec (global turn query, dedupe (session,turn), coalesce>4 to newest, template {{mode}}/{{ai_text}}/{{user_text}}, fixed-point whitespace-normalized cap 3, out/<session8>/<turn>.md, cursor seed at max ts).
- Known data quirk: stored `said` can be double-encoded (leading `"`) -> trim_double_encoded everywhere; mapper's own prompts start `mode: ` and must never bundle (self-map loop, hit twice in bash).
- tui.rs window fix landed on main checkout earlier: TuiChannel::open swaps TUI to tmux window 0 (commit 652b18f); `Multiplexer::swap_windows` uses `swap-window` (singular).

## Solution/Approach
- concatmap.rs = bash script port, no IR. Policy later via DL6 per plans (kept as plans only).
- Model pass through `Harness::one_shot` -> any adapter can be the mapper; opencode first impl.
- Remaining features requested but NOT built: reminder injection every N messages for context rot (bash crate had remind=A/B; port not yet), window-clipping compaction at context threshold (user prefers window clipping over handoff).
