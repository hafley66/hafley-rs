# docs/ writing rules

Applies to every file under `docs/` and every `crates/*/docs/` page (decision of
2026-09-20, memo `.claude/skills/2026-09-20-docs-no-code-cites`).

## Audience

The tool user. Someone who runs `ryi`, `boop`, `soopy` and wants a result. Not
the maintainer, not the reviewer, not the agent that wrote the code.

## Shape of every concept

1. Contrast first: the thing the reader could not say or do before.
2. Code in: the source file the reader would have, shown whole and small.
3. Query: the exact command or `.scm` the reader types.
4. Output out: the literal output of that command, produced by running it.

A concept without all four is a stub; leave it out of the page.

## Forbidden in a doc

- Source cites: no `file.rs:120`, no `src/...` paths, no Rust type or fn
  names. The reader has the binary, not the tree.
- A cite-verification gate in the brief. Verification is: every output block
  was produced by the command above it.
- The receipt block (`Boop-Check`, counted test results, gate output). Docs
  commits carry `Boop-Status` and `Refs-Issue` only.
- Term tables with a "where in the code" column.
- `honest`, `load-bearing`, `substrate`, `provenance`, `regime`, em dashes.

## Order inside a page

Problem, then what an existing tool can say, then what this tool can say, then
reference tables last. Never reference first.

## Delegation: the docs lane

| lane | loads | brief must | brief must not |
| --- | --- | --- | --- |
| `docs/<topic>` | `writing-documentation` skill, this file | name the fixture dir and the commands whose output fills the page; require every output block be regenerated by running it | ask for `file:line`, type names, a cite gate, or the receipt block |

The lane owns `docs/**` and one throwaway example dir it deletes before the
last commit. It never edits `src/`.
