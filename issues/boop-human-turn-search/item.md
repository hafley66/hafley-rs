# Search typed user turns separately from harness-injected user records

## Description

`agent_turn.role_id = user` currently means that the source transcript record
has `role: user`. It does not mean the text was typed by the person at the
terminal.

Codex records approval-review and continuation payloads as `response_item`
messages with `payload.role = user`. The payload is generated by the harness
and contains copied user, assistant, and tool text. `boop-store` projects every
such record through `project_line` as a normal `agent_turn` user row. Search
therefore finds words inside copied history and reports them as user messages.

This breaks the user-facing question: "which sessions did I respond positively
to?" A search for `yay`, `wow`, or `cool` must distinguish a direct message
from a copied occurrence inside an approval-review request, skill body,
command echo, transcript delta, task notification, or local-command event.

The raw transcript role remains useful and must remain queryable. The missing
fact is the turn's source class.

## Reproduction

The following existing Codex transcript contains a generated approval-review
message. Its raw record is a user message and its copied transcript contains
the word `cool`:

```bash
BOOP_NO_SYNC=1 boop db "
SELECT ds.value AS session, t.turn, r.value AS role, substr(t.said, 1, 220) AS said
FROM agent_turn t
JOIN dict_session ds ON ds.id = t.session_id
JOIN dict_role r ON r.id = t.role_id
WHERE ds.value = '019eb89b-74c4-7542-be4d-64ea94a68810'
  AND t.turn = 3;"
```

Observed result:

```text
role = user
said = The following is the Codex agent history whose request action you are assessing...
```

The raw JSONL source confirms why: the record is
`type=response_item`, `payload.type=message`, `payload.role=user`, immediately
after a `turn_context` whose model is `codex-auto-review`. Its content is an
approval-review envelope, not terminal input.

The present workaround is caller-maintained text filtering:

```sql
AND t.said NOT LIKE 'The following is the Codex agent history%'
```

It only covers one envelope spelling and cannot identify equivalent generated
records from other harnesses.

## Requested end state

Add a source class to stored turns and expose it through the read interface.

```text
boop db search wow --human --days 3650 --format text
```

returns only direct human input, across Codex, Claude, OpenCode, and future
harnesses. It returns session, harness, turn, timestamp, and text. It does not
require a caller-maintained list of `NOT LIKE` clauses.

Raw transcript search remains available without `--human`, and raw SQL can
still inspect every record.

## Acceptance Criteria

- [ ] `agent_turn` stores a source-class value distinct from its transcript
      role. The vocabulary includes `human`, `harness`, and `unknown`.
- [ ] The schema migration and `boop db sync create --rebuild` populate this
      value for existing transcript files.
- [ ] Codex projection marks approval-review and continuation envelopes as
      `harness`. Detection uses the surrounding record structure, including
      `turn_context.model = codex-auto-review`, rather than only a text prefix.
- [ ] Codex projection marks local-command events, command caveats, and
      injected instruction/skill bodies as `harness` when their source record
      identifies them.
- [ ] Each other harness adapter classifies records where its transcript format
      provides the distinction. Records without sufficient evidence are
      `unknown`; they are excluded by `--human`.
- [ ] `boop db search <text> --human` filters source class to `human` before
      applying the text predicate. Existing `boop db search <text>` behavior
      continues to search all stored text.
- [ ] Search output includes source class when `--format text` or NDJSON is
      selected, so a caller can audit why a row was returned.
- [ ] A Codex fixture contains one direct user message with `wow` and one
      auto-review envelope whose copied history contains `wow`. `--human`
      returns only the direct message.
- [ ] Fixtures cover at least one generated user-record family for Claude and
      OpenCode when their source formats expose one.
- [ ] `cargo test -p boop-store -p boop` passes.

## Implementation Notes

Current write path: `crates/boop-store/src/ident.rs:3027-3104`, where each
`record_type == user` text block is inserted with `role = user`.

The Codex chat projection has the same behavior in
`crates/boop/src/chat.rs:64-128`. Both projections need the same source-class
decision so direct transcript reads and SQLite searches agree.
